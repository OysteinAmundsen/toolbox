The Column Virtualization plugin improves performance for grids with many columns.

## Installation

```ts
import '@toolbox-web/grid/features/column-virtualization';
```

## Basic Usage

<Tabs syncKey="framework">
  <TabItem label="TypeScript">
```ts
import { queryGrid } from '@toolbox-web/grid';
import '@toolbox-web/grid/features/column-virtualization';

const grid = queryGrid('tbw-grid');
grid.gridConfig = {
  columns: generateManyColumns(100), // Your column generator
  fitMode: 'fixed', // Required for column virtualization
  features: { columnVirtualization: true },
};
```

Define everything inside `gridConfig.features`, exactly like the other frameworks. The side-effect import registers the feature so the adapter can bridge it.

```typescript
import '@toolbox-web/grid-angular/features/column-virtualization';
import { Component } from '@angular/core';
import { Grid } from '@toolbox-web/grid-angular';
import type { ColumnConfig, GridConfig } from '@toolbox-web/grid-angular';

@Component({
  selector: 'app-wide-grid',
  imports: [Grid],
  template: `
    <tbw-grid
      [rows]="rows"
      [gridConfig]="gridConfig"
      style="height: 400px; display: block;">
    </tbw-grid>
  `,
})
export class WideGridComponent {
  rows = [...];

  gridConfig: GridConfig = {
    columns: this.generateManyColumns(100),
    fitMode: 'fixed',
    features: { columnVirtualization: true },
  };

  generateManyColumns(count: number): ColumnConfig[] {
    return Array.from({ length: count }, (_, i) => ({
      field: `col${i}`,
      header: `Column ${i + 1}`,
      width: 120,
    }));
  }
}
```

:::note[Alternative: per-feature directive]
You can instead import `GridColumnVirtualizationDirective` and bind `[columnVirtualization]` directly on `<tbw-grid>`. That form gives a compile-time check that the feature is imported, but `gridConfig.features` above is the recommended, framework-consistent approach.

## Configuration Options

See [`ColumnVirtualizationConfig`](./interfaces/columnvirtualizationconfig/) for the full list
of options and defaults. By default the plugin activates itself once a grid exceeds 30 columns;
set `autoEnable: false` to control activation yourself.

## Requirements

- `fitMode: 'fixed'` — the plugin is designed for fixed-width column layouts
- Columns should have explicit widths (columns without widths default to 100px)

Pinned columns and utility columns (selection checkbox, master-detail expander, row-drag handle) are
never virtualized away: they are always rendered, so pinned ones stay visible while you scroll
horizontally. Unpinned utility columns scroll out of view like any unpinned column; pin them to keep
them on screen.

## Export, Clipboard and Column APIs

Virtualization only limits which columns are **rendered**. `grid.columns` and every column API
(`setColumnVisible()`, pinning, reordering, …) keep working on the full column list, including the
columns scrolled out of view. The [Export](/grid/plugins/export/) and
[Clipboard](/grid/plugins/clipboard/) plugins therefore include every column when you export or copy
without a cell selection, or pass `columns` explicitly.

If you also use the [Visibility plugin](/grid/plugins/visibility/), enable
`visibility: { searchable: true }` in `gridConfig.features` to help users find columns
in a long panel list. [Column search](/grid/plugins/visibility/#column-search) covers
the full column list, including hidden columns and columns outside the rendered
window. It only filters the panel list; virtualization controls what the grid renders.

## Selection and Focus

[Selection](/grid/plugins/selection/) ranges, the selection anchor, and the `col` of every
`CellRange` index the full list of visible columns, not the rendered window. A selection stays on its
columns while the grid scrolls horizontally, `selectAll()` (`Ctrl+A`) covers every column, and
copying or pasting a selection uses the selected columns even when they are scrolled out of view.
Column-mode selection (`selectColumn()`, `selectAllColumns()`, `getSelectedColumns()`) works on
columns outside the window too.

The focused cell also stays on its column. When you scroll it out of view, no cell shows the focus
ring and `grid.focusedCell.colIndex` is `-1`, while `grid.focusedCell.field` still names the column.
The next key press on the grid or one of its cells scrolls the column back into view before it is
handled, as in a spreadsheet. Keys typed into a control (an input or button rendered in a header or
cell) leave it scrolled out. `Home` / `End` go to the first / last column of the whole grid, not of
the rendered window.

Arrow keys and `Tab` step through every column: they scroll the next column into view instead of
stopping at the rendered window's edge or jumping into a pinned column.

A paste without a multi-cell selection writes into consecutive columns of the full list, so a wide
paste continues past the rendered window instead of stopping at its edge. A selected range pastes
into the columns it selects.

## Editing

Rows with open editors follow horizontal scrolling like other rows. An editor whose column stays in
view keeps its element, focus and draft, and columns that scroll into view get editors (in
`mode: 'grid'`, or on the row being edited in row mode). A focused editor whose column scrolls out of
view is blurred first, which commits its value. `Tab` in an editor continues to the next editable
column even when it is outside the rendered window, and
[`beginCellEdit()`](/grid/plugins/editing/) scrolls an off-window column into view before opening
its editor.

:::caution[Known limitations]

- **Resizing**: widening the grid or narrowing a column only re-windows on the next horizontal scroll
  ([#641](https://github.com/OysteinAmundsen/toolbox/issues/641)).
- **Responsive card layout** shows only the windowed columns
  ([#635](https://github.com/OysteinAmundsen/toolbox/issues/635)).

:::

**Accessibility**: screen readers still get the full grid. `aria-colcount` is the number of visible
columns, and each header and cell's `aria-colindex` is its position among all of them — not within
the rendered window.

The rendered window is computed **after** every other column plugin (pinning, grouping, pivot),
whatever their order in `plugins`, from their final output. Pinned order, group header rows, and
pivot columns are therefore preserved.

A custom plugin that maps columns onto rendered DOM cells by index should read
`this.visibleColumns` (the rendered columns) rather than `this.columns` (the full list).

## Programmatic API

```ts
const plugin = grid.getPluginByName('columnVirtualization');

// Check if virtualization is currently active
const active = plugin.getIsVirtualized();

// Get the visible column index range
const { start, end } = plugin.getVisibleColumnRange();

// Scroll a specific column into view
plugin.scrollToColumn(42);
```
