The Hierarchy plugin builds one hierarchical row model from every plugin that adds structure to the rows. [Tree](/grid/plugins/tree/) adds each row's children and [Row Grouping](/grid/plugins/grouping-rows/) groups lists of sibling rows. The two plugins never talk to each other, so they combine: with both enabled, the children of every tree node can be grouped.

You don't add this plugin yourself. Tree and Row Grouping depend on it, and the grid attaches it automatically. It has no configuration.

## Installation

Nothing to install. Importing Tree or Row Grouping brings the Hierarchy plugin along:

```ts
import '@toolbox-web/grid/features/tree';
import '@toolbox-web/grid/features/grouping-rows';
```

## How It Works

On every row-model rebuild the Hierarchy plugin walks the rows one sibling list at a time — the root rows first, then the children of each expanded node:

1. **Structure plugins** run first. Tree sorts the list and attaches the children of expanded nodes.
2. **Transform plugins** run next. Row Grouping replaces the list with group headers that contain the rows.
3. The result is flattened in display order.

Each plugin keeps ownership of its own expand/collapse state, events and API. `grid.getPluginByName('tree').toggle(key)` and `grid.getPluginByName('groupingRows').toggle(key)` keep working as before.

Read a row's position in the combined hierarchy with `getRowMeta`:

```ts
const meta = grid.getPluginByName('hierarchy')?.getRowMeta(grid.rows[0]);
// { level: 1, setSize: 2, posInSet: 1 }
```

## Accessibility

**[WCAG 2.2 SC 1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)** — nesting is conveyed to assistive technology, not only visually. While Tree or Row Grouping is active, the rows container uses `role="treegrid"`, and every rendered row — tree rows, group headers and grouped rows — carries `aria-level`, `aria-setsize` and `aria-posinset` for its position in the combined hierarchy. Rows that scroll into view get the same attributes. This is automatic; there is nothing to configure.

## CDN (UMD) Builds

`tree.umd.js` and `grouping-rows.umd.js` each bundle a copy of this plugin, so loading either one is enough.

:::caution[Deprecated]
The next major release stops bundling the Hierarchy plugin into those files. From then on, load `hierarchy.umd.js` first, or use `grid.all.umd.js`.
:::
